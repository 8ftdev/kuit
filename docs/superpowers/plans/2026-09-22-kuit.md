# Kuit Implementation Plan

**Goal:** Import local UI components into a minimal multi-framework documentation viewer.

**Architecture:** Go owns CLI configuration and validation. An embedded Bun helper resolves and copies source dependencies, then generates Astro routes and metadata. Astro compiles previews; React islands provide Fumadocs and the requested navbar.

**Tech Stack:** Go standard library, Bun, Vite, TypeScript parsers, Astro, Fumadocs, Tailwind, React, Vue, Svelte, Solid.

**Spec:** `docs/superpowers/specs/2026-09-22-kuit-design.md`

## Constraints

- Bun runs all JavaScript tooling; no npm commands.
- CLI syntax: `kuit <origin> <framework> [name]`.
- Preserve readable source; flatten dependencies with collision-safe names.
- Read-only Props table. No sidebar or TOC.
- Keep all component source under the target's framework/name folder.

## Tasks

- [x] CLI (`main.go`, `main_test.go`, `go.mod`): write validation tests, observe failure, implement argument/config handling and embedded helper execution. Run `go test ./...`.
- [x] Copier (`helper/*.ts`, `tests/import.test.ts`): write nested/cyclic/collision/alias/framework fixtures; observe failure; implement AST references, Vite resolution, staging, metadata and route generation. Run `bun test`.
- [x] Viewer (`site/`): configure four Astro renderers, Fumadocs code/props island, Cult UI treatment and upstream Ruixen navbar. Generate four sample bundles and run `bun run --cwd site build`.
- [x] Integration (`tests/`, `README.md`): verify CLI from a separate source directory; missing imports, conflicts and overwrite handling; browser-check desktop/mobile, tabs and live demos. Document installation and boundaries.
