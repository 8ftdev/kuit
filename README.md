# kuit

A small Go CLI that collects a UI component and its local dependencies into an Astro component library. JavaScript tooling runs with **Bun**. Supports **React, Vue, Svelte and Solid**.

## Start

Requires Go 1.23+ and Bun 1.2+.

```sh
bun install
bun run build:cli

# Save this viewer as the destination (use its absolute path).
./bin/kuit config set target "$PWD/site"

# Four small working examples are included.
bun run dev
```

Open <http://localhost:4321>. The home page links to Components, Snippets and Web Tools. Press **A**, **S** or **D** to open those sections; **M** opens the menu. Snippets and Web Tools are placeholders for now. The component viewer uses Astro, Fumadocs, the Ruixen expandable navbar and magnetic tabs, and Lineicons. There is no sidebar or table of contents.

To put `kuit` on your PATH:

```sh
go install .
# If needed, add "$(go env GOPATH)/bin" to PATH in your shell configuration.
```

## Import from any project

Run inside a source project with a `package.json`:

```sh
kuit ./src/button.tsx react shinny-button --install
kuit ./src/Button.vue vue
kuit ./src/Button.svelte svelte
kuit ./src/Button.tsx solid --export Button
```

`kuit <origin> <framework> [name]` defaults the name to the source filename, converted to kebab-case. The framework selects the renderer; it does not translate a React component into Vue or another framework.

For `kuit ./button.tsx react shinny-button`, the destination contains:

```text
site/
  react/shinny-button/
    shinny-button.tsx
    icon.svg
    ...local dependencies
    kuit.json
    preview-props.json
  src/pages/components/react/shinny-button/
    index.astro
    preview.astro
```

The page is available at `/components/react/shinny-button/`, with the framework index at `/components/react/`. Source imports such as `../../../assets/icon.svg` become `./icon.svg`. Dependencies are copied, never moved out of the source project. Conflicting basenames receive stable suffixes.

### Options

| Flag | Purpose |
| --- | --- |
| `--target /path/to/site` | Override the saved destination. `KUIT_TARGET` is also supported. |
| `--export Button` | Select a named export; otherwise choose default or the only capitalized export. |
| `--props '{"label":"Hello"}'` | Set serializable initial preview props. |
| `--install` | Run `bun install` in the viewer after a successful import. |
| `--force` | Replace an existing generated bundle, metadata and preview wrapper. |

`kuit config show` prints the saved target. Configuration lives in your platform's user config directory under `kuit/config.json`. `KUIT_CONFIG` overrides that file path.

An existing bundle is protected unless `--force` is supplied. Only folders identified as generated by Kuit can be replaced. Import errors are staged and leave existing output intact. `--force` deliberately replaces any manual changes inside that component bundle and its generated route directory.

## Previews and props

The page has **Preview**, **Code**, and **Props** tabs. Code includes all collected source files, syntax highlighting, line numbers and copy; its panel matches the Preview height (540px on desktop, 440px on mobile), with full-size text and scrolling. Binary assets remain in the bundle. Each preview runs in its own iframe to isolate component CSS from the viewer.

Edit `preview-props.json` for JSON props. For providers, callbacks, slots or other setup, edit the generated `preview.astro` and/or add a framework demo wrapper. A component requiring a router or application context cannot be mounted correctly without that setup. Required props are reported by the importer.

The Props table is best-effort static documentation, not interactive controls or a complete type checker. Local TypeScript interfaces/type literals, typed React/Solid function parameters, Vue `defineProps<T>()`, Svelte `$props()` and legacy `export let` are recognized. Complex inherited, computed or framework-specific runtime prop declarations may require manually editing the `props` array in `kuit.json`.

## Resolution and portability

- Vite resolves imports using the source project's config. TypeScript path aliases are supported as a fallback. Install the source project's dependencies first if its Vite config imports plugins.
- Imports, re-exports, literal dynamic imports, `require()` references, `new URL(..., import.meta.url)`, CSS imports/URLs and Vue/Svelte static image attributes are traversed. Copying a `require()` reference does not itself convert CommonJS to browser ESM.
- Package imports stay as package imports. Their declared versions are recorded in `kuit.json` and added to the viewer's `package.json`. Existing differing versions are kept with a warning; resolve compatibility yourself. No whole `node_modules` directory is copied.
- Computed dynamic imports, `import.meta.glob`, virtual modules and local `workspace:`/`file:` package dependencies are rejected rather than silently exporting an incomplete bundle.
- Global application CSS, Tailwind config/theme tokens, environment values, routes, providers and plugin-specific transforms are not inferred. Add shared styles to `site/src/styles/preview.css` and needed integrations to `site/astro.config.mjs`. Plain Vite image-import URL semantics are preserved by the included adapter.
- This is source collection, not arbitrary application migration. Only reachable dependencies are collected; unreferenced public files, runtime-created paths, HTML `srcset`, and asset strings assembled in code are not discovered.
- The source Vite config is executed during resolution. Use source projects you trust.

To use a different local library, copy the `site/` template, run `bun install` inside it, and configure that path as the target. All helper dependencies are declared in the template; the Go binary embeds the helper and does not depend on this checkout. Restart the viewer after adding routes if an existing dev session has not picked them up.
